# نیازمندی‌های کارکردی

| کد | نیازمندی |
|---|---|
| FR-1 | مدیر می‌تواند برای هر نوع سند یک الگوی شماره اندیکاتور تعریف یا ویرایش کند. اجزای الگو: پیشوند متنی، سال مالی، کد دسته‌بندی، شماره ترتیبی با طول ثابت و جداکننده (BR-8). نمونه: `CTR-1405-0045`. |
| FR-1.1 | هنگام تعریف الگو، یک شماره نمونه پیش‌نمایش داده می‌شود. |
| FR-2 | کاربر دارای مجوز ثبت می‌تواند روی سند بدون شماره، اقدام «ثبت در اندیکاتور» را انجام دهد و سیستم شماره بعدی را طبق الگو تخصیص دهد. |
| FR-3 | پس از ثبت، شماره و تاریخ و کاربر ثبت روی سند نمایش داده می‌شود (صفحه سند، فهرست اسناد). |
| FR-4 | شماره اندیکاتور قابل ویرایش یا حذف نیست، حتی توسط مدیر. |
| FR-5 | کاربران می‌توانند اسناد را با شماره اندیکاتور جستجو و فیلتر کنند. |
| FR-6 | اسناد موجود، یک‌بار و خودکار، به‌ترتیب تاریخ ایجاد شماره می‌گیرند. |
| FR-7 | اسنادی که از سیستم قدیمی import می‌شوند هم به‌ترتیب تاریخ ایجادشان شماره خودکار می‌گیرند. |
| FR-8 | ثبت شماره در لاگ فعالیت با زبان ساده ثبت می‌شود. |
| FR-9 | اقدام ثبت فقط برای کاربران دارای مجوز «ثبت در اندیکاتور» نمایش داده و پذیرفته می‌شود. مدیر این مجوز را به نقش‌ها می‌دهد. |
| FR-10 | مدیر یک الگوی پیش‌فرض کلی تعریف می‌کند که برای نوع‌های سند بدون الگو استفاده می‌شود. |
| FR-12 | مدیر برای هر نوع سند یک کد کوتاه یکتا تعریف می‌کند. اسناد قدیمی فقط پس از تعریف کد برای نوع سندشان شماره‌دهی می‌شوند (سؤال Q9). |
| FR-11 | شماره اندیکاتور روی صفحات چاپ و پیش‌نمایش سند درج می‌شود (کنار واترمارک). |
